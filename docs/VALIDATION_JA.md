# 検証記録

2026-11-05。履歴・観察タブ・上下の詳細へのUI改修と、WASMアプリの配布構成を検証しています。コンパイラのCrystalコードとビルド済みWASMは前版から変更していません。

## 検証環境と対象

- Linux x86_64、Node 24.22.1、Python 3
- 全工程エンジン: Crystal 1.22.0 + browser-crystal WASI/EHパッチ、LLVM 20.1.8、LLD
- 軽量構文エンジン: Crystal 1.23.0-devの固定ソース
- 共通のWASIホスト: browser_wasi_shim 0.4.2（npmロックから取得）

Nodeでブラウザと同じWASMバイナリ・WASIホスト・コンパイル経路を実行します。JavaScriptでCrystalの処理を模倣するテストではありません。

## テストの範囲

| 確認項目 | 方法 |

| 例外と回復 | rescue・ensure、構文／型エラー後の新しいコンパイル |

`make samples`は実際のブラウザ用WASMをNodeで起動します。7例はリンク成功、型エラーの1例は診断と実行ファイル未生成を確認し、全例を確認してから圧縮記録を更新します。

## 実行コマンド

```sh
make web-deps
make samples
make test
npm run lint
npm run format:check
```

Crystalコードを変更した場合は先に`LLVM_CONFIG=llvm-config-20 make browser`と`make wasm`で配布WASMを再生成します。全工程ビルドはリンク後に`WebAssembly.compile`で妥当性を確認してから資材とハッシュを更新します。

## Chromeで確認した操作

- 英語で初期表示。JA/EN切替時にソース・履歴位置を維持し、選択言語と仕切り位置を再読み込み後も復元。
- 上部40pxの1行、履歴が左、Source/AST等が中央、ノード詳細が右上、Visitor/操作詳細が右下。
- Source内の初期コード選択・サンプル記録の表示。編集すると「Custom code」に切り替わる。
- 色分けされた65行以上の日本語・補間入りコードを編集。縦横スクロールの同期と、textarea/色分け層の文字・行寸法の一致を確認。
- Normalizerの書き換え履歴を選び、`x += 2`から`x = x + 2`への変化と役割の説明を表示。別ASTノードを選んでも操作説明を維持。
- 横と上下の仕切りの矢印操作、初期配置に戻す操作、履歴の折り畳み、観察領域の最大化、タブの矢印操作。
- 編集したマクロ・日本語・コレクションのコードをCompile & runで実行し、`結晶 46`と`1,9,16`を確認。
- 別の入力をCompile → IRでLLVMへ変換し、OutputのRun againで`結晶 42`を確認。
- Parse onlyで未完の`def broken(`に対する実際のEOF診断を表示し、その後の正常入力でAST生成へ回復。

## 検証の限界

Node上のWASM・JavaScriptモデルと、Chromeの画面・操作を確認しました。GitHub Actions上のジョブ実行や公開操作は行っていません。日本語テキストの保持は確認しましたが、各OSのIME操作やすべての支援技術の検証は行っていません。

全Crystal specの通過や、すべてのブラウザ・任意の外部ライブラリへの対応を意味しません。WASIに適合する単一入力を扱い、OSプロセス、ソケット、外部Cライブラリを必要とするコードには制約があります。生成プログラムはGCなしです。入力・時間・メモリ・出力の上限は[設計書](ARCHITECTURE_JA.md)に記載しています。
